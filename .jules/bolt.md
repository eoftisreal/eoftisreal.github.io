## 2024-05-25 - React State Full-Page Re-Render Bottleneck
**Learning:** Using `useState` to track visual UI state (like `currentSlide` for a carousel) that updates frequently (e.g., via scroll events or intervals) without actually rendering that state in the JSX causes massive, silent performance bottlenecks. In `HomePage.tsx`, updating `currentSlide` in state triggered full re-renders of the entire page and all child components (`ProductCard`, categories) every time the interval fired or the user scrolled, completely wasting CPU cycles since the value was never painted to the DOM.
**Action:** Always audit `useState` hooks. If a value is updated frequently but never rendered in the UI (only used for calculations or DOM interactions), it must be tracked with `useRef` to prevent unnecessary component tree re-renders.
